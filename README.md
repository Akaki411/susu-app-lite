# ЮУрГУ lite

PWA-приложение: расписание, рейтинг БРС, электронный пропуск (QR), новости и сервисы университета.
Быстрое, современное, автономное и отказоустойчивое при плохой или отсутствующей сети.

Интерфейс доступен на шести языках: русский, английский, французский, испанский,
арабский и китайский.

## Требования

- [Bun](https://bun.sh) ≥ 1.4.0 (используется как рантайм и пакетный менеджер)
- Node.js ≥ 22.18 (нужен для `rari`-CLI, который сам пишется под Node/Bun окружение)

## Установка

```bash
bun install
cp .env.example .env
```

`bun install` автоматически запускает `scripts/patch-rari-runtime.mjs` (см. ниже, зачем).
Заполните `.env` — минимально нужен `IS_DEV=true` для локальной разработки.

## Разработка

Запуск в режиме разработки:

```bash
bun run dev
```

Откройте адрес, который выведет команда (порт Vite не фиксирован, обычно :5173). API-роуты
(`/api/*`) работают в том же процессе - отдельный бэкенд запускать не нужно.

### Добавление сервисов

Чтобы добавить сервис - скопируйте `src/services/service-example.tsx`, поменяйте иконку/
подпись/логику клика (ссылка/модалка/iframe/переход по роуту) и добавьте сервис в массив `services`.

## Продакшн

Перед продакшн запуском требуется сначала выполнить сборку:

```bash
bun run build
bun run start
```

Для отказоустойчивости рекомендуется держать процесс через systemd/docker и настроить проксирование
на 443 порт через nginx (готовый nginx-конфиг под приложение в `nginx.example.conf`). В `.env` для
продакшн режима требуется убрать `IS_DEV` (или поставьте `false`), но требуется предустановленный **Redis**.

## Управление данными

**Персональные данные пользователя не хранятся на сервере.** Токены авторизации и профиль студента
(ФИО, группа, контакты и т. п.) хранятся только в `localStorage` браузера пользователя. Сервер выступает 
лишь в качестве прокси к внешнему API для обхода CORS.
**Проложение собирает только обезличенную статистику** использования и хранит ее в БД.
Ради быстродействия **используется кеширование** расписания и рейтинга.

#### Администраторы

Панель статистики в разделе «Сервисы» видна только администраторам. Добавить администратора
можно в любой момент скриптом по `userId`:

```bash
bun run addadmin <userId>
```

Также первого администратора можно задать через переменную `ADMIN_SEED` в `.env` (см. комментарий там).
